# Переносы

2026-09-30: самостоятельное приложение выделено из прототипа по поручению владельца. Копируется только код. Библиотека, доски, оценки, заметки и история исходного проекта остаются на месте. Карта конкретных путей и проверяемый снимок хранятся в исходном проекте, вне GitHub.

Заполнять строку для конкретного действия. Не использовать таблицу как разрешение на последующие несвязанные переносы.

2026-10-07, профиль и подпись записей (DESIGN.md, «Профиль и кто что изменил»): формат только дополняется. В события, версии, уведомления и пресеты добавлено необязательное поле `by`, появились `<state>/people/<id>.json` и `<state>/boards/_events/_files.jsonl`. Старые записи не переписываются и читаются как раньше. Перенос папки доски между общей и личной папкой запускает сам человек из меню доски, после вопроса: переименование на том же диске, проверенная копия и Корзина для старой папки с другого диска.

2026-10-07, участники и агенты (DESIGN.md, «Участники и агенты»): формат только дополняется. `via` в новых записях теперь вид из каталога (`claude`, `codex`, `gemini`, `kimi`, `opencode`, `agent`, `app`), старые записи с именем агента не переписываются, страницы сводят имя к виду при показе. В `profile.json`, `people.json` и карточках `<state>/people/<id>.json` появились необязательные `avatar` (data URL) и `agents` (`{вид: время}`), в `people.json` еще `hidden`.

2026-10-07, аннотации и комментарии (DESIGN.md, «Аннотации и комментарии»): новые папки рядом с `notes`, `annotations/` и `comments/`, по файлу на рисунок и на обсуждение, и `reads.json` рядом с профилем. Доски, картинки и их json не меняются. В событиях страниц новые виды (`comment`, `reply`, `annotate` и другие), старые читатели показывают их как прочие события.

2026-10-08, слияние сохранений (DESIGN.md, «Одновременные правки одной доски», `review/merge.py`): формат доски только дополняется. Сервер при записи ставит в файл страницы `vid`, `parent`, `edited` и `by`; старые файлы без них читаются как раньше, их основа ищется по номеру ревизии. Старое приложение эти поля сохраняет, как любые неизвестные. Новое: кэш основ вне Dropbox (`~/Library/Caches/Hyimg/<id доски>/bases/`, удаляемый без потерь), события `merge` и `dropbox`, папка `boards/_history/<страница>/dropbox/` для слитых конфликтных копий (копии туда переносятся, не удаляются). Устаревшее сохранение больше не получает 409, а сливается.

2026-10-08, Архив на Главной (DESIGN.md, абзац «Архив на Главной», `review/ui/homearchive.js`): `home.json` только дополняется. В `folders` появляется проект с id `archive` и полями `from` (из какого проекта пришла доска) и `merged`. При первом показе Главной проект владельца с именем Archive, _Archive или Архив один раз сливается в архив: его доски переходят туда, сам проект уходит из списка, а его id, имя, иконка, цвет и список досок остаются в `folders[archive].merged`, по ним проект можно вернуть. Каталог, папки досок и их данные не трогаются, поэтому отдельного снимка нет: меняется только группировка на Главной, и прежнее ее состояние сохраняется в том же файле.
